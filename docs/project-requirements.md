# 可视化全栈项目工程平台：需求与架构文档

## 产品定位

这是面向企业研发团队的可视化全栈项目工程平台，形态类似 IDEA 或 VS Code 的桌面开发工具，并配套中央控制服务器。平台用于构建和维护前台、后台及响应式移动 Web 项目：画布模型可编译为真实工程代码，受规范约束的代码变更可反向解析回画布。

平台不负责生成真实数据库、真实外部系统接入或复杂业务逻辑；首期面向单体应用。

## 设计原则

- 画布中的路由、页面嵌套、级联、权限和响应式效果必须与生成项目一致。
- 画布是主要搭建入口，树形结构仅辅助定位。
- 项目模型、技术栈模板与确定性编译器是权威；Agent 仅辅助检查和建议。
- 手写代码可存在，但无法安全解析的内容必须保留为扩展区，不能被重新编译静默覆盖。
- 项目模型和源代码共同进入 Git/SVN，中央服务不成为模型唯一存储位置。

## 总体架构

```text
桌面客户端（画布、VS Code 兼容编辑、本地工作区、离线 Git、预览）
        │
        ▼
中央控制服务器（组织权限、项目、模板、组件、版本库、编译、解析、CI/CD、通知、审计）
```

服务端支持内网与云部署，采用容器化交付。客户端采用跨平台架构，首期保证 Windows；Linux/macOS 的构建、路径、Docker 与自动化测试需提前兼容。

## 组织、权限与项目

组织结构为“组织—部门—用户”。优先对接 OA、LDAP/AD 等身份系统；没有时平台内部维护。项目由部门管理，用户以个人身份提交与协作。

权限覆盖项目、仓库、组件、环境、模板、部署和审批。页面、菜单、按钮三级权限预留在项目模型中；启用时画布模拟权限效果，编译器生成路由、菜单和操作权限骨架。

项目工作台采用左侧项目列表、中间画布/预览/代码、右侧属性/问题/通知的布局。未编译项目显示画布缩略预览；已编译项目提供绘制、代码、构建部署与版本审批入口。

## 项目模型与双向编译

仓库中使用 `.visual-project/` 保存页面、组件、路由、权限、国际化与代码映射等模型文件；`.platform/` 保存技术栈锁定、扩展策略与部署配置。

```text
绘制模型 → 确定性编译器 → 源代码 → Git / SVN
                                  ↓
                              手写修改
                                  ↓
Git / SVN → 受限源码解析器 → 模型更新与画布差异展示
```

生成代码必须具有稳定语义标识。工程分为引擎托管层、用户扩展层、受保护生成区、保留代码区与冲突处理区。无法反向解析、模型冲突或不规范代码必须生成可指派、可通知、可关闭的待处理事件。

## 技术栈与组件

用户仅可选择验证过的技术栈模板。首批覆盖 Vue 3 + TypeScript、React + TypeScript、Java + Spring Boot、Python + FastAPI、Node.js + NestJS。每套模板需定义工程结构、组件映射、代码规范、构建测试、编译规则与反向解析规则；先完成少量模板的完整闭环后再扩展。

组件分为平台基础组件、项目私有组件和组织共享组件。共享组件由负责人确认发布后才进入组织资产库。定制组件允许符合模板的少量代码扩展，但不承载真实业务数据、数据库或真实外部系统调用。

## 离线协作与扩展

客户端支持离线编辑、预览和本地 Git 提交。实时协同中断网时自动退出协同并回归本地变更；联网后按 `main`、`develop`、功能分支、发布分支的 Git 合并流程同步。

代码编辑复用 VS Code 兼容编辑器与扩展生态。离线本地扩展默认只能访问当前项目工作区；项目外文件、终端和网络需显式授权或组织策略批准。联网扩展必须签名、登记、审批、声明权限并受审计。网络、文件等特殊能力只能在隔离容器中模拟验证。

## 版本控制、CI/CD 与制品

支持 GitHub.com、GitHub Enterprise、通用 Git SSH/HTTPS 与 SVN。源代码以版本库为唯一权威来源。

CI/CD 可选择分支、标签或提交构建，执行检查与测试，并用 Docker 部署到 Linux 测试服务器。支持平台自带流水线及后续对接 Jenkins。每个项目维护独立测试环境标识、域名/端口和环境变量。

内置镜像仓库只用于开发、测试与迁移过渡；生产优先使用企业 Harbor 或 Docker Registry。支持迁移镜像、标签、制品元数据和部署引用。候选版本需测试人员和项目负责人确认后才标记为稳定；审批流可启用、配置和拆卸。

服务端加密保存 Git、SVN、Jenkins、镜像仓库与服务器凭据，按组织、项目和环境授权，后续可对接 Vault。

## 通知、Agent 与安全

首期使用平台内通知中心，涵盖解析失败、冲突、构建/测试/部署失败、审批、稳定版本、扩展审批与异常安全事件。后续可对接 OA、邮件、企业微信和钉钉。

Agent 在编译前提供配置、命名、样例数据和完整性建议；编译后测试阶段可基于结果提出修复建议。不得静默修改模型或决定核心业务逻辑。接入外部编程工具后，内置 Agent 可隐藏或降级。

核心权限、密钥、审批、制品签发、部署控制、审计与高价值编译能力必须在服务端。客户端与更新包需签名和完整性校验；令牌绑定组织、用户、设备和能力范围。篡改客户端不能调用受控服务端能力。技术防护无法绝对阻止客户端逆向，但应使破解版本失去组织协作、部署、资产、受控编译和持续服务能力。

## MVP 顺序

1. 中央服务基础：组织、权限、项目索引、审计和通知。
2. 统一项目模型、稳定语义标识、技术栈模板接口。
3. Windows 客户端：工作台、画布、代码编辑、本地工作区和 Git。
4. GitHub/GitHub Enterprise/通用 Git 与 SVN 连接器。
5. 至少一套前端模板的绘制、编译、手写修改、反向解析、冲突闭环。
6. Docker Linux 测试部署、内置镜像仓库、稳定版本标记。
7. 企业镜像迁移、Jenkins、审批流、组织组件、联网扩展治理。
8. 更多语言模板、实时协同、已有仓库导入、OA 集成。

## 运行态绘制与 Mock 数据补充

绘制采用可多开的独立“运行态绘制窗口”，与主系统分离。主系统展示项目概览、Mock 数据、版本记录、检查报告、协作和发布；绘制窗口仅用于可运行页面的直接搭建。拖入组件后，组件应立即成为页面中可交互、可预览和可跳转的一部分，而不是静态拼装预览。

- 绘制不使用庞大的右侧属性/数据/事件/样式面板。
- 选中组件后通过页面内浮动操作和右键菜单完成常用设置；右键可选择“样式微调”或“编辑样式代码”。
- 样式微调应提供间距、圆角、颜色、对齐等紧凑操作；`Ctrl` 多选组件后可组合、统一调整或绑定事件。
- 左侧保留紧凑组件轨道。自定义组件必须由 Agent 扫描功能后生成可视缩略图卡片；悬停显示真实效果预览，拖入即可使用，不能仅用文本标签。
- 界面默认跟随操作系统明暗主题，并允许用户显式覆盖。

Mock 数据属于主系统的项目级 Tab，不应作为绘制窗口中的属性配置。它仅用于预览、编译和测试，不连接生产数据；用户定义字段结构、命名规则、枚举、约束和生成数量，Agent 在规则约束下生成并由引擎校验测试数据。
