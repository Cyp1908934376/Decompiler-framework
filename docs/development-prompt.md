# 开发提示词

你是一名企业级开发工具、低代码引擎、IDE 客户端和 DevOps 平台架构师。请设计并逐步实现一个可视化全栈项目工程平台。

产品是类似 IDEA / VS Code 的跨平台桌面开发工具，配套支持内网和云部署的中央控制服务器。首期以 Windows 为交付重点，但构建、路径、Docker 和测试需兼容 Linux/macOS。

核心目标：用户以真实页面画布构建前台、后台和响应式移动 Web 项目；画布模型确定性编译为真实工程代码；符合技术栈规范的手写代码可受限反向解析回画布；支持离线编辑、本地 Git 提交、联网合并、组织协作、Docker 测试部署、审批和稳定版本。

请严格遵循：

1. 首期仅支持单体应用，不实现微服务、集群和分布式治理。
2. 画布中的路由、嵌套、权限和响应式行为必须等同于生成项目的运行效果。
3. 项目模型保存于版本库的 `.visual-project/`，源代码和模型共同版本化；中央服务只保存索引、权限、构建、部署、审批、通知和审计元数据。
4. 使用稳定语义标识定位生成区、页面、组件、字段和事件。无法解析的手写代码必须保留在扩展区或保留代码区，不能静默覆盖。
5. 解析失败和冲突必须产生可指派、可通知、可关闭的事件。
6. 技术栈只能由验证过的模板提供。首批范围为 Vue 3 + TypeScript、React + TypeScript、Java + Spring Boot、Python + FastAPI、Node.js + NestJS；先完成少量模板的完整双向闭环。
7. 支持 GitHub.com、GitHub Enterprise、通用 Git SSH/HTTPS 和 SVN。
8. 客户端支持离线编辑、预览和本地 Git 提交；协同中离线时退出协同，恢复后采用 Git 分支合并。
9. 代码编辑复用 VS Code 兼容能力。离线扩展默认只访问当前项目工作区；文件系统扩展、终端和网络须明确授权。联网扩展需签名、审批、权限声明和审计。
10. CI/CD 支持平台自带 Docker Linux 测试部署，并预留 Jenkins 对接。内置镜像仓库仅用于测试和迁移过渡；生产支持迁移至 Harbor/Docker Registry。
11. 候选版本需测试人员和项目负责人确认后标为稳定。审批流必须可选、可配置、可拆卸。
12. 服务端保存权限、密钥、审批、制品签发、部署控制、审计和高价值编译能力。客户端需签名与完整性校验；篡改版本不得调用受控服务。

绘制体验必须额外满足：

- 绘制是可多开的独立“运行态绘制窗口”，与主系统的项目概览、Mock 数据、版本、检查、协作和发布功能分离。
- 拖入组件后即成为可运行页面的一部分；不得实现为静态拼装预览或传统属性面板驱动的低代码编辑器。
- 不设置庞大的右侧属性/数据/事件/样式面板。选中组件后使用页面内浮动操作、右键菜单和紧凑样式微调；右键可切换配置式样式调整或样式代码调整。
- 支持 Ctrl 多选组件并统一绑定事件、组合或调整。
- 左侧组件库保持紧凑。自定义组件由 Agent 扫描功能后生成可视缩略图卡片；悬停展示功能预览，不能仅以文本标签呈现。
- Mock 数据为主系统中的项目级 Tab，仅用于预览、编译和测试；由字段规则约束 Agent 生成，禁止接入生产数据，也不作为绘制属性配置。
- 所有界面默认跟随系统明暗主题，并允许用户覆盖。

按以下顺序实施：

1. 输出模块边界、部署拓扑、数据流、目录结构和风险清单。
2. 定义项目模型 TypeScript 类型或 JSON Schema，以及模板、组件、编译器、源码解析器、版本库、CI/CD 的接口。
3. 实现中央服务的最小组织、项目、权限、通知、审计能力。
4. 实现 Windows 客户端的项目工作台、画布、代码编辑、本地工作区和 Git。
5. 实现一套技术栈的绘制、编译、代码扩展、反向解析、差异和冲突闭环。
6. 实现 Docker 测试部署、构建记录、候选版本与稳定版本。
7. 实现扩展沙箱、客户端完整性检查和权限测试。

每一阶段都必须给出可运行的最小示例、输入输出边界、单元测试、最小端到端测试、未实现能力和待确认项。不得擅自编造业务逻辑或以 Agent 替代确定性引擎。
